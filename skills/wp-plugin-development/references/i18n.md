# Internationalization (i18n) and RTL

Use this file whenever a plugin outputs user-facing text.

## PHP

| Need | Function |
| --- | --- |
| Return / echo a string | `__()` / `_e()` |
| Escaped for HTML / attribute | `esc_html__()`, `esc_html_e()`, `esc_attr__()`, `esc_attr_e()` |
| Disambiguate with context | `_x()`, `esc_html_x()` |
| Plurals | `_n()`, `_nx()` (with `number_format_i18n()` for the number) |
| Dates | `wp_date()` with a translatable format |

```php
/* translators: %s: reviewer display name. */
printf( esc_html__( 'Review by %s', 'acme-reviews' ), esc_html( $name ) );

printf(
	/* translators: %d: number of reviews. */
	esc_html( _n( '%d review', '%d reviews', $count, 'acme-reviews' ) ),
	(int) $count
);
```

Rules:

- The text domain is a literal string equal to the plugin slug. Never a variable or constant: extraction tools parse source code statically.
- The string is a literal too; no variables inside `__()`.
- Use placeholders (`%s`, `%1$s`/`%2$s` when there are several) instead of concatenating sentence fragments; word order differs between languages.
- Add a `/* translators: */` comment directly above any string with placeholders.
- Keep HTML out of strings where possible; when needed, use `wp_kses()` with a minimal allow list or `sprintf()` the markup in.
- Don't translate data (option keys, slugs, log messages meant for developers).

## Loading translations

- Plugins hosted on WordPress.org get language packs from translate.wordpress.org, loaded just in time. `load_plugin_textdomain()` is not needed for them (since WP 4.6).
- Plugins shipping their own translations (not on WordPress.org) call `load_plugin_textdomain( 'acme-reviews', false, dirname( plugin_basename( __FILE__ ) ) . '/languages' )` on `init`.
- WP 6.7+ emits `_doing_it_wrong` ("Translation loading for the `acme-reviews` domain was triggered too early") when a translation function runs before `init`. Common causes: translating in a constructor run on `plugins_loaded`, in a top-level constant, or in a class property default. Move the call into a hook at `init` or later.
- WP 6.5+ prefers `.l10n.php` translation files (generated with `wp i18n make-php`) over `.mo` for performance; language packs include both.

## JavaScript

- Use `@wordpress/i18n` (`__`, `_n`, `sprintf`) with the same text domain.
- Register translations for the script handle: `wp_set_script_translations( 'acme-reviews-editor', 'acme-reviews' )` (third argument: path for self-hosted JSON files). For blocks registered via `block.json`, core does this automatically when `textdomain` is set.
- For self-hosted translations, generate JSON files with `wp i18n make-json languages --no-purge`.

## Tooling

```bash
wp i18n make-pot . languages/acme-reviews.pot --exclude=node_modules,vendor,build
wp i18n make-json languages --no-purge
wp i18n make-php languages
```

Run `make-pot` in CI or before release so the template matches the code.

## RTL

- Check `is_rtl()` only when logic (not styling) depends on direction.
- Ship RTL stylesheets and register them with `wp_style_add_data( $handle, 'rtl', 'replace' )`; prefer CSS logical properties so one stylesheet works both ways.
- Test admin screens and frontend output with an RTL locale (for example `fa_IR`, `ar`, `he_IL`).
